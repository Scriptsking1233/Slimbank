# SlimBANK на GitHub Pages + Supabase

Сайт лежит на GitHub Pages (бесплатно, только статика), аккаунты, баланс,
юзернеймы и промокоды — в Supabase (PostgreSQL + авторизация, тоже бесплатно).

## Состав пакета

```
index.html               сам сайт (версия 18 + подключение сервера)
slimbank-config.js       твои ключи Supabase (единственный файл, который надо править)
slimbank-supabase.js     мост: вход, регистрация, синхронизация, промокоды
supabase/schema.sql      вся база и серверные функции (один запуск)
.nojekyll                чтобы Pages не ломал файлы
```

## Шаг 1. Создать проект Supabase

1. Зайди на supabase.com → **New project** (регион поближе, пароль БД сохрани).
2. Подожди 1–2 минуты, пока проект поднимется.

## Шаг 2. Создать таблицы

1. В проекте: **SQL Editor** → **New query**.
2. Вставь целиком содержимое `supabase/schema.sql` → **Run**.
3. Должно написать *Success*. В **Table Editor** появятся `profiles`, `promo_codes`,
   `promo_redemptions`, `plans`, `audit_log`.

## Шаг 3. Настроить вход

**Authentication → Providers → Email**:

- включён **Email**;
- **выключить «Confirm email»** — иначе аккаунт не активируется, ведь в банке
  логин — телефон, а не почта;
- если есть пункт «Allow new users to sign up» — он должен быть включён.

Как это работает: номер `+7 903 118-22-40` превращается в служебный e-mail
`79031182240@slimbank.local`, пароль — тот, что человек ввёл при регистрации.
Входить можно по телефону, почте или @юзернейму — это делает серверная
функция `find_login`.

## Шаг 4. Вставить ключи

**Project Settings → API**: скопируй **Project URL** и **anon public key**,
вставь в `slimbank-config.js`:

```js
window.SLIM_SUPABASE = {
  url: "https://abcdefgh.supabase.co",
  anonKey: "eyJhbGciOi...",
  autoRegister: true,
  serverAccruals: true,
  serverPromos: true,
  debug: false
};
```

`anon key` публичный, его нормально держать в репозитории.
**`service_role` ключ в репозиторий класть нельзя никогда.**

## Шаг 5. Залить на GitHub Pages

```bash
git init
git add .
git commit -m "SlimBANK v18 + Supabase"
git branch -M main
git remote add origin https://github.com/<твой-логин>/slimbank.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Source: Deploy from a branch**,
branch `main`, folder `/ (root)` → Save. Через минуту сайт будет здесь:
`https://<твой-логин>.github.io/slimbank/`

Ссылка на сайт работает по HTTPS — Supabase требует именно HTTPS, так что Pages подходит идеально.

## Шаг 6. Проверка

1. Открой сайт, внизу слева должен гореть индикатор «Сервер: готов к входу».
2. Зарегистрируйся → индикатор станет зелёным («аккаунт создан»), а в
   Supabase → Table Editor → `profiles` появится строка с твоим балансом.
3. Открой сайт с телефона, введи те же телефон и пароль → приедет тот же счёт.
4. Введи промокод `WTHJW` в профиле — его проверит сервер, второй раз
   он уже не сработает ни в каком браузере.

## Что теперь на сервере

| Функция | Где считается |
|---|---|
| Регистрация и вход (пароль хранится хешем) | Supabase Auth |
| Баланс и все данные счёта | таблица `profiles` |
| Начисления каждые 10 минут (до 48 ч офлайна) | `claim_accruals()` |
| Промокоды, один код = один раз | `redeem_promo()` |
| Уникальные юзернеймы для всех игроков | `username_free()`, `claim_username()` |
| Топ игроков по балансу | `leaderboard()` |
| Лог подозрительных рывков баланса | `audit_log` |

Казино, бизнесы, кредиты, аукцион и подарки пока считаются в браузере и просто
сохраняются в `profiles.state` — значит, технически подкованный игрок ещё может
накрутить себе числа через консоль. Второй этап — перенести эти действия в такие
же RPC-функции (`buy_business`, `casino_play`, `loan_take`), тогда клиент вообще не будет
решать, сколько у человека денег.

## Если сервер недоступен

Код написан так, что при отсутствии сети или ключей сайт работает как раньше —
на локальном хранилище браузера, индикатор покажет «Офлайн».
Так что сначала можно выложить сайт без ключей, а Supabase подключить позже.
